# Kiro History - Daily News Widget Development

## 2026-03-03 - Initial Development Session

### Project Overview
Built "Inference News" - a macOS widget for aggregating LLM inference optimization news from 12 sources.

### Key Features Implemented
1. **Async Collection with Progress Tracking**
   - Non-blocking article collection using QThread
   - Real-time progress updates showing source name and article count
   - Progress bar (0-100%) during collection
   - Final summary: "Done! X new articles"

2. **Data Sources (12 total)**
   - arXiv (cs.LG, cs.AI, cs.CL categories)
   - RSS Feeds (9): Hugging Face, PyTorch, vLLM, Google AI, OpenAI, Microsoft AI, SemiAnalysis, Together.ai, NVIDIA Developer
   - Anthropic (2): Research and Engineering blogs

3. **UI/UX**
   - Frameless, translucent window with rounded corners
   - Expand/collapse toggle (⤢/⤡) between 550×850px and 400×500px
   - Source filter dropdown (250px button, 300px list)
   - Auto-initialize database on first run
   - Draggable, resizable window
   - Minimize button for window management
   - Entire article card clickable to open URL
   - Hover effect on article cards

4. **Gemini Integration**
   - ✨ button on each article for AI summarization
   - Copies prompt to clipboard and opens Gemini web app
   - Simplified prompt: "Summarize this article: [title] [url]"
   - Dark tooltips with proper styling via QPalette

5. **Visual Indicators**
   - 🔥 icon for new articles (not yet viewed)
   - ✨ icon for Gemini summarization
   - Dark theme with rgba(28, 28, 30, 0.95) background

6. **Technical Solutions**
   - **Anthropic Date Extraction**: Used sitemap.xml to get accurate publication dates (avoiding JS-rendered page issues)
   - **Relevance Scoring**: Keyword-based filtering for most sources, no filtering for SemiAnalysis, Microsoft AI, vLLM, Together.ai, NVIDIA
   - **Database**: SQLite with auto-cleanup (180 days retention)
   - **Event Handling**: Proper event propagation for clickable cards with separate Gemini button

### Architecture
- **Widget**: PyQt5-based standalone app
- **Collectors**: Modular collectors for each source type (arXiv, RSS, web scraping)
- **Database**: SQLite with Article model (title, url, source, date, summary, relevance_score, tags)
- **Config**: YAML-based configuration for sources and keywords

### Deployment
- macOS app bundle with embedded Python environment
- Installed in /Applications/
- Launch script activates venv and runs widget.py

### Git Repository
- Repository: github.com:kailashbuki/inference-news.git

- .gitignore for Python cache, database, and generated files

## 2026-03-12 - Fixed Widget Crash on Refresh

### Bug
App crashed every time the refresh (↻) button was pressed.

### Root Causes
1. **Missing airealist_collector in widget**: `CollectionThread` in `widget.py` was never updated when AI Realist source was added on Mar 6. Only `collect_all.py` was updated.
2. **boto3 not in venv**: `arxiv_collector` imports `bedrock_classifier` which requires `boto3`. boto3 was installed in system Python (`~/.pyenv/versions/3.8.18`) but not in the project `.venv`. The venv had `include-system-site-packages = true`, masking the issue during development. The app bundle only copies `.venv`, so boto3 was missing at runtime.

### Fixes
- Added `airealist_collector` import and call to `CollectionThread.run()` (7 collectors now)
- Updated progress bar denominator from 6 to 7
- Installed boto3 directly into `.venv/lib/python3.8/site-packages/`
- Updated `create_app.sh` to include `icon.png`, `icon_rounded.png`, and `bedrock_classifier.py`
- Rebuilt app bundle and deployed to `/Applications/`

### Commits
- `88ee191` - Add missing airealist collector to widget
- `d6010d6` - Install boto3 into venv for bedrock_classifier

## 2026-09-23 - Migrated from macOS widget to a static web app

### Goal
Move everything online. Target: GitHub Pages project page at
https://kailashbuki.github.io/inference-news/ (the kailashbuki.github.io root is
occupied by the Jekyll homepage, and its Rakefile force-pushes a generated _site
over master, so nesting the dashboard in that repo would have been clobbered by
the next blog rebuild).

### Privacy scrub (prerequisite for going public)
Audited the working tree and every blob in all 14 commits.
- Four live Twitter credentials sat in config.yaml from the very first commit
  (5a06443), so every commit carried them. Purged with git filter-repo
  --replace-text; verified 0 occurrences remain. THE KEYS MUST STILL BE REVOKED
  at developer.twitter.com - treat them as compromised.
- Purged both tracked articles.db blobs and the whole "Inference News.app"
  bundle from history.
- Clean: no AWS account ids, ARNs, /Users paths, emails, or internal hostnames.
- filter-repo dropped the origin remote, so nothing can be pushed by accident.
- Backup of pre-rewrite state: ~/Workplace/inference-news-backup-20260923/
  (verified full-history bundle, all three DBs, original config).
- Rewriting history changed every commit SHA, so the hashes cited in the
  Mar 6 / Mar 12 entries above no longer resolve.

### Architecture change
No server. GitHub Actions runs the collectors on cron, commits JSON, deploys Pages.
- data/articles.json is now the source of truth: diffable in git, served as-is.
- store.py hydrates an in-memory SQLite DB from that JSON and dumps back after,
  so all five collectors keep their SQLAlchemy session interface UNCHANGED.
- Verified hydrate -> dump is lossless over all 744 seed articles.

### Data recovery
Three databases had diverged and none was a superset:
  articles.db (repo root)                 133 rows, newest 2026-03-06
  Inference News.app/.../articles.db      274 rows, newest 2026-09-21
  /Applications/.../articles.db           598 rows, newest 2026-07-14
Merged all three by URL -> 744 unique articles spanning 2025-10-09..2026-09-21.
The widget's 180-day cleanup used to delete old rows; retention is now a display
filter instead, so nothing is thrown away.

### Bedrock -> Gemini
bedrock_classifier.py authenticated through a local AWS profile backed by a
privileged work account. That credential cannot and must not be exported to
GitHub Actions, and the profile name is not recorded here. Replaced with
classifier.py calling the Gemini REST API, reading GEMINI_API_KEY from the env
only (never config.yaml), with responseSchema for structured output, a 4.5s
throttle for the free tier's 15 rpm, a per-run call cap, and automatic fallback
to relevance_scorer.py on missing key / 429 / any error. Dropped boto3.

### Retired
widget.py, create_app.sh, launch_widget.sh, dashboard_server.py, scheduler.py,
bedrock_classifier.py, twitter_collector.py, reddit_collector.py (both were
disabled). requirements.txt went from 14 pins to 6.

### Verified locally
- Full collection run: 35 new articles in 61s (keyword fallback path, no key set).
- Site assembled as the workflow does and served under /inference-news/: all
  assets 200, all refs relative, so no base-URL config is needed.
- node --check on app.js, yaml parse on the workflow.
