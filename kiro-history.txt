# Kiro History - Daily News Widget Development

## 2026-03-03 - Initial Development Session

### Project Overview
Built "Inference News" - a macOS widget for aggregating LLM inference optimization news from 12 sources.

### Key Features Implemented
1. **Async Collection with Progress Tracking**
   - Non-blocking article collection using QThread
   - Real-time progress updates showing source name and article count
   - Progress bar (0-100%) during collection
   - Final summary: "Done! X new articles"

2. **Data Sources (12 total)**
   - arXiv (cs.LG, cs.AI, cs.CL categories)
   - RSS Feeds (9): Hugging Face, PyTorch, vLLM, Google AI, OpenAI, Microsoft AI, SemiAnalysis, Together.ai, NVIDIA Developer
   - Anthropic (2): Research and Engineering blogs

3. **UI/UX**
   - Frameless, translucent window with rounded corners
   - Expand/collapse toggle (⤢/⤡) between 550×850px and 400×500px
   - Source filter dropdown (250px button, 300px list)
   - Auto-initialize database on first run
   - Draggable, resizable window
   - Minimize button for window management
   - Entire article card clickable to open URL
   - Hover effect on article cards

4. **Gemini Integration**
   - ✨ button on each article for AI summarization
   - Copies prompt to clipboard and opens Gemini web app
   - Simplified prompt: "Summarize this article: [title] [url]"
   - Dark tooltips with proper styling via QPalette

5. **Visual Indicators**
   - 🔥 icon for new articles (not yet viewed)
   - ✨ icon for Gemini summarization
   - Dark theme with rgba(28, 28, 30, 0.95) background

6. **Technical Solutions**
   - **Anthropic Date Extraction**: Used sitemap.xml to get accurate publication dates (avoiding JS-rendered page issues)
   - **Relevance Scoring**: Keyword-based filtering for most sources, no filtering for SemiAnalysis, Microsoft AI, vLLM, Together.ai, NVIDIA
   - **Database**: SQLite with auto-cleanup (180 days retention)
   - **Event Handling**: Proper event propagation for clickable cards with separate Gemini button

### Architecture
- **Widget**: PyQt5-based standalone app
- **Collectors**: Modular collectors for each source type (arXiv, RSS, web scraping)
- **Database**: SQLite with Article model (title, url, source, date, summary, relevance_score, tags)
- **Config**: YAML-based configuration for sources and keywords

### Deployment
- macOS app bundle with embedded Python environment
- Installed in /Applications/
- Launch script activates venv and runs widget.py

### Git Repository
- Repository: github.com:kailashbuki/inference-news.git

## 2026-03-12 - Fixed Widget Crash on Refresh

### Bug
App crashed every time the refresh (↻) button was pressed.

### Root Causes
1. **Missing airealist_collector in widget**: `CollectionThread` in `widget.py` was never updated when AI Realist source was added on Mar 6. Only `collect_all.py` was updated.
2. **boto3 not in venv**: `arxiv_collector` imports `bedrock_classifier` which requires `boto3`. boto3 was installed in system Python (`~/.pyenv/versions/3.8.18`) but not in the project `.venv`. The venv had `include-system-site-packages = true`, masking the issue during development. The app bundle only copies `.venv`, so boto3 was missing at runtime.

### Fixes
- Added `airealist_collector` import and call to `CollectionThread.run()` (7 collectors now)
- Updated progress bar denominator from 6 to 7
- Installed boto3 directly into `.venv/lib/python3.8/site-packages/`
- Updated `create_app.sh` to include `icon.png`, `icon_rounded.png`, and `bedrock_classifier.py`
- Rebuilt app bundle and deployed to `/Applications/`

## 2026-09-23 (evening) - Rebranded to "roofline", widened scope, batched the classifier

### Why the repo had to be recreated
Force-pushing the scrubbed history was NOT sufficient. GitHub keeps unreachable
objects accessible indefinitely: after the push, all four original commits were
still fetchable by SHA, and the pre-rewrite config.yaml (with the Twitter keys)
was still readable via
  gh api "repos/<owner>/<repo>/contents/config.yaml?ref=5a06443"
Verified 2 secret lines still present on the remote. So a private->public flip
would have published exactly what the scrub was for. Lesson: scrubbing history
locally does not scrub what the remote already stored; only a fresh repo (or a
GitHub Support purge) is deterministic.

### New identity
Name: roofline, after the roofline model - arithmetic intensity vs peak
compute/memory bandwidth - the one abstraction spanning the whole scope.
URL: https://kailashbuki.github.io/roofline/
Branding: amber #ff6b35 (compute-bound) with blue #4aa3ff (memory-bound) as the
second accent, wordmark + favicon drawn as the roofline kink (SVG, no bitmap).
Deleted icon.png / icon_rounded.png (4.3MB of retired-app art) and favicon.png.
localStorage keys renamed inference-news:* -> roofline:*.

### Scope widened
From inference-optimization-only to the full stack: model architecture and
algorithms, training and scaling, post-training, inference optimization, serving
systems and engines, systems-level work, and AI chips.
- arXiv categories += cs.AR, cs.DC, cs.PF; query_terms rewritten as a broad

- Tag taxonomy rewritten: architecture, training, post-training, inference,
  serving, systems, hardware, quantization, attention, compression,
  optimization, multimodal, benchmarks, llm.
- Added a tag filter to the UI.

### Keyword filtering removed; Gemini used efficiently instead
Keyword matching was a bad relevance signal. Every candidate now goes to the
model. Affordable because of three things:
1. BATCHING - one request carries 20 articles and returns one verdict each,
   keyed by an echoed id. ~330 single calls per run becomes ~17. Out-of-order
   ids, missing entries and wrapped arrays are all handled; gaps fall back
   per-item rather than discarding the batch.
2. Dedup before classify - stored URLs are never re-sent.
3. data/rejected.json - a rejection ledger, so the ~90 off-topic stories in a
   HackerNews top-100 are judged ONCE, not 3x/day forever.
   Subtlety: only *model* rejections are recorded. A keyword-scored rejection is
   a low-confidence guess made while the API was unavailable, so recording it
   would permanently block a real verdict later. classify_many therefore returns
   (score, tags, judged_by) and pipeline.commit checks judged_by.
Feeds that are wholly on-topic set filter: false - still classified for tags,
never dropped on score.
Collectors refactored to two-phase (gather candidates -> batch classify ->
store) via the new collectors/pipeline.py. HackerNews keyword prefilter deleted.

### Gemini API notes (it moved under us)
- gemini-2.0-flash is RETIRED. Default is now gemini-3.5-flash-lite.
- generateContent is NOT deprecated ("remains fully supported") and is the
  default here; it was the only surface that reliably returned 200.
- The Interactions API works at /v1beta/interactions with gemini-3.6-flash and
  gemini-3.8-flash. The migration guide's /v1beta2/interactions is WRONG - 404
  with an empty body on every model.
- max_output_tokens INCLUDES thought tokens, and Gemini 3 thinks by default
  (floor is thinking_level minimal/low, never off). A 200-token cap truncated
  the JSON mid-object; budget is now 2048 + 120/article.
- responseSchema must be supplied or the model invents key names (it returned
  is_relevant instead of relevant). generateContent wants UPPER-case type names.
- The larger models frequently 503 "high demand" on the free tier; flash-lite
  does not. Transient 5xx now retries 3x with backoff.
- Free-tier RPM/RPD are no longer published per model; they are per-project in
  AI Studio. verify_gemini.py probes what a given key actually supports.
